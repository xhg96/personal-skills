# Vibe Coding 文档规范：spec.md 与 unspec.md

## 背景

Vibe Coding 中，代码由 AI 编写，人类不再阅读代码，而是通过自然语言文档掌控代码：读文档就能知道代码是怎么实现的；即使代码全部丢失，凭文档也能复现。

为此，agent 修改到的每个目录下都有两份文档，按内容是否经人类确认来划分：

| 文件 | 内容 | 效力 |
|------|------|------|
| `spec.md` | 人类提出或确认过的内容 | 代码必须完全遵守 |
| `unspec.md` | 所有未经人类确认的实现，即 agent 自行决定的部分 | agent 可以自由改动，但文档必须与代码一致 |

人类读 spec.md，知道自己定下了什么；读 unspec.md，知道其余部分是怎么实现的。

## 规范

### 适用范围

- 新仓库（还没有代码）直接执行本规范。已有代码的仓库，人类要求启用后才执行；没有启用时，不要创建这两份文档。
- 已启用的标志是仓库根目录有 `spec.md`：新仓库在第一次写代码时创建它，已有代码的仓库在人类要求启用时创建它。

### 两份文档的共同要求

- agent 修改到的每个目录（包括新建的目录），都必须有 `spec.md` 和 `unspec.md`；没有修改到的目录不需要。`.git` 和被 `.gitignore` 忽略的目录除外。
- 一份文档只描述它所在的目录。涉及子目录或其他目录时，用相对路径链接到那里的文档，不在本文档中展开。
- 可读性要高：用尽量简短、高效的结构把内容写完整。简短是目标，不设篇幅上限，前提是内容完整。

### spec.md

- agent 按人类的指示修改代码，同时把这些指示写进 spec.md。spec.md 只记录人类提出或确认过的、关于代码应该怎样的内容，以对话为准，逐条列出；没有这样的内容时，只写"暂无"。
- "确认"指人类针对某项具体内容明确表示同意。对整份方案或大段输出笼统回复"可以""继续"，不算确认了其中的每个细节。
- 按人类的原意记录，不扩大、不缩小、不替人类补充细节。
- 已记录的内容，代码必须完全遵守；没有记录的，由 agent 自由发挥。
- spec.md 的内容只随人类的话变化：人类改口时，直接改写对应条目；agent 不得自行增删改。要求之间有冲突或无法实现时，交给人类决定。
- 一条要求只涉及某个目录时，记在该目录；涉及多个目录时，记在它们共同的上级目录。

### unspec.md

- 记录本目录中所有未经人类确认的实现，例如接口、数据结构、流程与算法、常量、错误处理、依赖、配置。局部变量名、代码格式这类不影响行为的细节不用记。
- 完整的标准：删掉本目录的代码后，只凭文档就能把它复现出来。
- 始终与代码一致：代码变了，unspec.md 同步更新。
- 不重复 spec.md 已有的内容。某项内容得到人类确认后，把它从 unspec.md 移到 spec.md。

### 工作方式

- 修改一个目录下的代码前，先读它和各级上级目录的 spec.md，这些要求都适用于它。
- 修改一个还没有文档的目录时，为它补上文档：unspec.md 按现有代码写；spec.md 不能从代码反推。
- 每次修改完成后确认三点：人类在对话中提出或确认的内容都已写进 spec.md；代码遵守相关的 spec.md；unspec.md 与代码一致。
